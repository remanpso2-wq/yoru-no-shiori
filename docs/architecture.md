# 設計判断

## 正解と手がかりの秘匿

`cases.mjs` はAPIからのみ参照する問題バンク。カタログは紹介文だけに絞る。`view` は参加者ごとに手がかり本文を選別し、終了前に正解・正解の証拠ペア・解説・認証ID・再送履歴を返さない。

根拠判定は応用2話のみ。作者が設計した決め手のペアとの一致を判定し、自由記述の意味理解を行うAI判定ではない。将来AI出題を実装する場合も別途、唯一解と根拠整合性の評価が必要。

## 同時操作

Room JSONとrevisionをD1へ保存。現在のrevisionを条件にUPDATEし、競合したら最新状態から遷移を再計算（最大4回）。書込みの上書き消失を防ぐ。再試行でも同じ操作IDを使い、直近64件の受付済み操作を重複適用しない。IDは参加者ごとに分離し、異なる内容での使い回しを409で拒否。

画面は約2秒ごと（非表示時8秒）にポーリング。古いrevisionの到着で画面を巻き戻さない。WebSocketではない。重複排除の保持範囲外や部屋作成には完全なexactly-onceを保証しない。

## ホスト引継ぎ

参加者の順序は変えずホストIDのみ変更。証拠の担当者が変わる問題を防ぐ。引継ぎ後は旧ホストに回答・ヒント権限を与えない。終了後・存在しない相手・自分自身への引継ぎは拒否。

明示的な引継ぎのみで、突然の切断に対する自動移譲は未実装。勝手な権限奪取につながらないよう、将来はサーバー側の在席期限と復帰の扱いを定義してから追加する。

## 公開境界

Sitesの所有者限定アクセスを維持。部屋にはCookieで参加者を識別し、Origin一致、JSON形式、ストリーム読み込み4KiB上限、入力検証を適用。Cookie変更による作成制限の回避、ルームコード総当たり、IP単位の制限などは一般公開前の追加課題。現状を公開サービスの安全性保証としない。
